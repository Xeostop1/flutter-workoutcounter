Google Play 출시 준비를 이어서 진행해줘. 나는 Flutter 초보자이고 개발은 이 맥북에서 하고 있어. 현재 최신 수정은 아직 GitHub에 푸시하지 않았어.

준비 자료는 https://github.com/Xeostop1/flutter-workoutcounter 의 codex/play-materials-20261102 브랜치, release/google-play-20261102/에 있어. 이 브랜치 전체를 checkout해서 맥의 최신 앱을 교체하지 마. 자료 커밋은 release 폴더만 추가하므로, 기존 작업을 먼저 보존한 뒤 해당 자료 커밋만 안전하게 가져와줘. 단일 브랜치 clone이라 원격 ref가 안 보이면 명시적인 refspec으로 이 자료 브랜치만 fetch하고 기존 ref/소스는 덮어쓰지 마.

먼저 현재 실제 프로젝트 경로/remote/브랜치/HEAD/미커밋 파일을 확인하고 내 작업과 기존 iPhone 서명/계정 데이터를 보존해줘. Windows의 예전 체크아웃으로 덮거나 pull/reset/clean/force push 하지 마. 원격의 codex/android-verification-20261101/41662ca는 이전 인계본이지 지금 맥의 최신본이 아니야.

우선 현재 맥 작업을 검토/검사하고 소스·앱 자산·lockfile만 안전하게 release/google-play-20261102 같은 별도 브랜치에 커밋/푸시해줘. .p8/keystore/key.properties/.env/서비스계정키/local.properties/게스트파일/인증로그/빌드 산출물은 올리지 마. 최신 브랜치 이름과 커밋을 알려줘. 필요한 인증은 내가 직접 할게.

다음으로 현재 Google Play 신규 앱 제출 기준(API36 이상)을 공식 문서에서 확인하고 최신 프로젝트의 실제 compileSdk/targetSdk와 AGP/Gradle/JDK/Flutter 호환성을 점검해줘. 이전 인계본은 target35/AGP8.7.3/Gradle8.12/Flutter3.32.4였지만 지금 코드를 먼저 확인해야 해. 필요 최소한으로 도구 조합을 이행하고 iOS 파일은 유지해줘. API 숫자 하나만 바꾸고 통과라고 하지 마.

사용자는 개인 Play 개발자 계정이 있고 지원 이메일은 stop1@daum.net이야. 무료 운동 카운터 앱으로 준비 중이야. 계정 생성일/프로덕션 권한/실제 기기 확인/테스터 요구는 아직 콘솔에서 확인 전이야. 필요하면 내가 직접 할 절차만 안내하고 가짜 테스터나 에뮬레이터로 실제 기기 확인을 우회하지 마.

release AAB 서명은 기존 키/업로드 이력부터 확인해줘. 기존 키를 교체하거나 채팅으로 비밀번호/키 파일을 요구하지 마. 최초 배포이고 기존 키가 없다는 확인 후에만 업로드 키를 준비하고 안전한 별도 백업을 안내해줘. AAB의 versionCode는 콘솔의 최대 업로드값보다 높아야 해. 실제 패키지는 기존 com.sparkleteamhns.counter01을 함부로 변경하지 마.

빌드 전 analyze/테스트, 일반 lib/main.dart 실행, Android15/16 및16KB 환경을 확인해줘. actual release AAB/merged manifest/64bit.so의16KB ELF 정렬과 APK ZIP 정렬/서명을 검사하고, Play에서 설치한 내부 테스트 앱까지 확인해줘. 로컬 debug 통과를 Play release 성공으로 보고하지 마.

설정창에서 입력 후 취소/적용/시작, 실제 TTS1초/2초 및 휴식 순서, 일시정지/재개, 운동 중 화면 켜짐/종료 후 해제, 게스트 운동 완료 저장→재실행 후 동일ID 유지→기존 계정 로그인 병합 중복 없음/기존 기록 보존을 재검증해줘. 로그인과 청취는 내가 직접 처리할 수 있게 안내해줘. 기존 기록 삭제/임의 탈퇴로 검사하지 마. 테스트 계정 탈퇴 데이터 삭제만 별도로 확인해줘.

Google 로그인은 Mac debug/upload 인증서 외에 Play App Signing의 앱 서명 SHA-1/SHA-256이 Firebase/OAuth에 등록됐는지도 확인해야 해. Google/Apple 로그인 제한과 심사 접근 방법을 분리하고 개인 계정 비밀번호를 심사 자료로 공유하지 마.

새 프로모션 ZIP에는 원본22개가 있고, Windows에서 배너1024x500 및1080x1920 후보7개를24bit RGB PNG로 무손실 형식 변환했어. 픽셀 동일 검사와 기술 규격 검사는 통과했지만 후보 이미지의 UI/프레임/버튼 문구/달력 목표는 최신 Android 앱과 대조 전이야. 아이폰 형태라고 무조건 사용 불가라고 단정하지 말고 실제 Android 경험과 일치시켜줘. 최신 앱 아이콘512x512도 준비해야 해. 앱 내부 그림/아이콘을 임의로 새 디자인으로 바꾸지 마.

공개 개인정보처리방침/계정 삭제 요청 URL은 아직 미확정이야. 이전 약관에는 운영자/리전 확정 필요 문구와 서버 삭제 함수 설명이 있었으니 최신 코드/실제 배포와 대조해줘. 운영자/책임자/리전/보관기간은 추측해서 공개하지 마. 지원 이메일 stop1@daum.net을 사용할 수 있어. 웹 삭제 요청은 앱 재설치를 강요하지 않고 본인 확인 후 연관 데이터까지 처리되게 해야 해.

Data safety/건강 앱(Activity and Fitness)/광고 포함/대상 연령/IARC/심사자 접근 안내를 최신 의존성과 실제 동작 근거로 준비해줘. Firebase와 클라우드 기록이 있는데 수집 없음으로 일괄 답하지 마. Health Connect 미사용이 건강 기능 없음과 같지는 않아. 서명키/운영 데이터/사적인 인증 로그는 Git에 넣지 마.
