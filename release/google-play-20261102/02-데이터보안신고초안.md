# Data safety 및 개인정보처리방침 점검 초안

**최종 신고 답안이나 법률 검토 완료 문서가 아닙니다.** 기준은 이전 인계본41662ca이고, 맥의 최신 코드/실제 release 산출물/SDK의 공식 데이터 공개를 다시 확인해야 합니다. 사용자 확인 지원 이메일은stop1@daum.net입니다.

| 데이터/항목 | 이전 코드에서의 근거 | 최종 확인할 내용 |
|---|---|---|
| 이름/닉네임, 이메일, 사용자ID | Firebase Auth, 사용자 프로필 | 최신 로그인/설정 저장 경로, 수집 목적과 선택 여부 |

| 운동 메모/자유 입력 | 기록/루틴 입력 | 기타 사용자 콘텐츠 분류 여부와 실제 저장 필드 |

## 초안 원칙

- 로그인/클라우드 기록을 지원하므로 모든 데이터를 '수집하지 않음'으로 신고하지 않습니다.
- 게스트 이용 가능은 서버 전송 시점/선택성 판단에 도움이 되지만 모든 항목이 선택 수집이라는 자동 결론은 아닙니다.
- Firebase가 처리 수탁자/서비스 제공자인지와 정책상 '공유'의 예외 적용은 SDK 용도와 실제 데이터 사용을 확인해야 합니다. Firebase를 쓴다는 이유만으로 모두 공유 또는 모두 미공유로 답하지 않습니다.
- HTTPS/암호화 전송은 최신 네트워크 경로까지 확인합니다. 삭제 가능 여부는 실제 연관 데이터 삭제 검증 뒤 답합니다.
- Health Connect/센서 권한을 쓰지 않아도 운동 기록은 Fitness info 및 Activity and Fitness 건강 기능 신고와 관련됩니다.
- 아동 대상/정확한 대상 연령은 운영자 결정이 필요합니다. 보호자 동의·가족 정책·광고 SDK 관련 답변을 임의로 만들지 않습니다.

## 공개 개인정보처리방침 확정 전 필요한 사실

1. 최종 앱/개발자 표시명과 운영자/개인정보 책임자 표시.
2. 실제 Firebase 저장 리전·인증/SDK 수탁 관계와 국외 이전 사항.
3. 서버/기기별 실제 수집·보관·삭제 범위. 서버 함수를 쓰는지 클라이언트 삭제인지 최신 구현과 배포 상태 확인.
4. 게스트 기록/백업/로그인 병합·미저장 대기 기록의 처리. 앱 제거 시 백업에서 복구될 수 있는지 포함해 과도한 삭제 보장을 하지 않음.
5. 삭제 요청 본인 확인 방식, 회신/처리 일정과 법적 보관 예외가 있다면 근거·대상·기간.
6. 공개 정책 URL과 계정 삭제 URL. `stop1@daum.net`은 연락처이며 URL을 대신하지 않습니다.

법적 사실이 미확정된 템플릿을 그대로 공개하거나 운영자명/리전/기간을 임의로 채우지 않습니다. 공개 전 최신 동작과 관련 법령 검토가 필요합니다.
